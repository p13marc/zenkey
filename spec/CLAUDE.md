# spec

Claude Code loads this file when working in `spec/`; the root `CLAUDE.md` is the index.

- **`spec/`** holds what every implementation must agree on. Its two
  normative texts are `core.md`, what participants put on the wire and
  how owners, consumers, callers and deployments behave, and
  `observer.md` (#925), what a tool, or any participant reading presence,
  state or the admin space, does with what it reads, when a read is
  complete, and what it may conclude and tell a person. Each states its
  version in its header and records every change in its own changelog
  (`CHANGELOG.md`, `observer-CHANGELOG.md`), and
  `scripts/check-spec-status.sh` keeps each header naming its changelog's
  newest entry and README.md and spec/README.md stating neither number.
  A rule states itself and cites its evidence, and nothing more (#935,
  core 0.60, observer text 0.4): the amendment that made it and the
  finding that caused it are its changelog's, and measurements and one
  zenoh binding's facts are core Appendix B's, the rule keeping its
  reason in words and a pointer. `scripts/check-spec-prose.py` (the fmt
  job, the Docs lane and `just ci`) holds every `.md` under `spec/`, and
  under `docs/guide/` once it exists, to `spec/.prose-baseline.json`: each
  text's mean words per sentence, its sentences over 50 words (35 under
  `docs/guide/`) and its inline history tags only go down. `--update`
  lowers the baseline and records a new file; a rise is a hand edit of
  the baseline, which a reviewer sees. `--list <file>` prints a text's
  long sentences and tags with their lines. Core 0.66 (#926) claims
  conformance by role (§12): one class each for owner, consumer, caller,
  deployment and observer (§0's tool role, named for `observer.md`), each
  its role's rules in both texts plus the static rules (§1's, §9's, those
  on what a contract states in the sections §12 lists, §2.2, §2.4, §2.5,
  §2.6, §3.1, §7.1 and §10, and any rule naming the lint code checking
  it). An implementation claims one
  class per role it plays; full is the level of a class claimed without
  the constrained modifier, the five classes' union being every rule of
  both texts, so what conformed still does; constrained modifies a class,
  its table kept; a
  profile is a class of its own, claimed by following it. A reader's rules
  (observer.md §0) belong to the class of the role the reader plays.
  `spec/RULES.md` lists every MUST, MUST NOT, SHOULD and SHOULD NOT of
  `core.md` and `observer.md` by role, then by section, with its rule ids
  and evidence, and a table of the rule ids (R, S, O, D, E, W). It is
  generated by `scripts/gen-rules-index.py` (standard library only, on
  `check-spec-prose.py`'s reading of blocks and sentences), which reads a
  rule's role from its subject by §0's role words and plain synonyms, and
  fails naming the line of a rule whose role it cannot read: the cure is a
  sentence that names its role, never an entry in its empty `EXCEPTIONS`.
  Where a subject names no role it reads only a passive's agent, a run-in
  role label (for the sentence it opens alone), a pronoun's antecedent in
  the same paragraph, or a static rule by the list it reads from §12's
  sentence "The static rules are …" (or a lint code): never a section's
  title, and a pronoun with no antecedent there is unread, not static.
  `--how` (`--how=other`) prints how each rule's role was read, for an
  audit. A reader's rules are listed once, under observer, marked
  *reader*, and the owner, consumer and caller sections each point to them.
  After a change to either text run `python3 scripts/gen-rules-index.py`
  and commit `RULES.md`: `--check` (the fmt job, the Docs lane and `just
  ci`) fails when it is stale, and `--self-test` reads
  `scripts/fixtures/rules-index/`. A stream-only owner's minimum path is
  the index's owner and implementation entries. `spec/README.md` opens
  with a glossary, each term linked to its defining section; its
  baseline only goes down too. Core 0.67 and observer text 0.9 (#926
